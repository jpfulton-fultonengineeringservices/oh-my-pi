# Fork changelog

Changes this fork carries on top of upstream `can1357/oh-my-pi`. Upstream's
`packages/*/CHANGELOG.md` files are kept verbatim, so a rebase onto a new
upstream tag never has to merge into them; fork-only entries live here instead.
Entries are oldest first, one per change, prefixed with the subsystem they touch.

- coding-agent/extensions: deferred extension loading now initializes native transcript presenter state and supports presenter registration/disposal and shortcut-conflict lookup through the supported factory API.
- coding-agent/tests: `test/rpc-wire/native-extension-smoke.ts` proves native extension discovery, mounted dispatch, independent MCP failure isolation and session switch/resume against the production binary, with every model, embedding, MCP and SSH call scripted locally.
- pi-ai: `applyProviderReportedCost` admits any provider when the wire echo carries a finite, non-negative `usage.cost`, and the BYOK `cost_details.upstream_inference_cost` fold is flag-driven rather than keyed to OpenRouter/ClinePass, so a gateway that reports an authoritative charge is no longer priced from token estimates.
- internal-urls: `knowledge://record/<context>/<track>/<id>` and `knowledge://track/<context>/<track>` resolve against the memvid-kb-rs record service. The workspace `.memvidkb` decides which context and which tracks a session may read, and both are checked before any network call; every refusal and outage is a non-empty explanation carrying a specific `notes` code, an outage is never reported as zero results, and a superseded or unproven record is never presented as current.
- bash/git-guard: `bash.gitGuard` treats a checkout under a `.git-worktrees/` directory as a private checkout, so path `checkout`, `switch`, `reset --hard` and `stash` run there — including in a git submodule nested in one — after saving discarded uncommitted changes to `refs/omp/discarded`.
- coding-agent/extensions: a tool call refused by approval policy is now observable to extensions — the wrapper emits it as an error `tool_result` carrying the tool input and the refusal text the model would have received, so a `tool_result` handler may substitute the model-visible content (the `bash` → dedicated-tool redirect is the intended user). A denied call still never executes, and when no extension listens, or a listener stays silent, the refusal throws exactly as before.
- internal-urls: the `knowledge://` handlers reuse the central helpers instead of local equivalents — the shared `withTimeoutSignal` for the service fetch, `isRecord`/`stringProperty` for service bodies, `isEnoent`/`isEnotdir` for `.memvidkb` probing, `walkUp` for the upward config search, and `sanitizeText` + `replaceTabs` + `shortenEmbeddedPaths` + `truncateToWidth` with `TRUNCATE_LENGTHS` for every service string that reaches rendered markdown. `DEFAULT_RECALL_MAX_BYTES` is exported instead of mirrored by callers, and both knowledge modules are star-exported from the `internal-urls` barrel like every sibling scheme.
- coding-agent/tests: `test:native-extension-smoke` is wired as a `pi-coding-agent` script (`bun run test:native-extension-smoke`) and proves the tree under test: with no binary argument it runs `src/cli.ts` through `bun`, and the extension fixtures are read from the agent directory; the JSONL audits are parsed with `Bun.JSONL` and appended through a `Bun.file` writer. Its `tool_details` check now requires the tool's declared parameter properties to reach the render instead of counting characters, and that check is red today: `xd://` tools render an empty parameter block, because `ToolInfo.parameters` is an ompType schema — a function — and a consumer that JSON-round-trips it stores `{}`; `irToJsonSchema(schema.ir)` from `@oh-my-pi/omptype` is what emits the properties. With that one check relaxed the harness passes end to end (native discovery, mounted dispatch, SSH audit, MCP failure isolation, session switch/resume), so the script is an honest red proof of a real gap rather than a green. The knowledge protocol suite drops `process.chdir` (the handler takes the workspace to search) and asserts rendered content — expanded tabs, a `~`-shortened home path — where it previously asserted only that a string was non-empty.
